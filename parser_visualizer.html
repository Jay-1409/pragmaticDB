Parsing Pipeline

The journey of a SQL string through the parser, from raw text to an executable plan.

1
Raw SQL
Text received over TCP socket from client
→
2
Tokenize
Split by whitespace via std::istringstream
→
3
Dispatch
Route to ParseSelect, ParseCreate, etc.
→
4
Parse JOIN
Detect JOIN ... ON, call ParseExpression
→
5
Expression AST
Recursive descent builds the condition tree
→
6
Statement
Returns SelectStatement with AST attached
📝
End-to-End Example
Following a query through each step
── Step 1: Raw SQL arrives over TCP ──
"SELECT * FROM users JOIN orders ON users.id = orders.user_id AND users.active = true;"

── Step 2: Tokenized by std::istringstream ──
[ SELECT  *  FROM  users  JOIN  orders  ON  users.id  =  orders.user_id  AND  users.active  =  true; ]

── Step 3: Dispatch → Parser::Parse() reads "SELECT" → calls ParseSelect() ──

── Step 4: ParseSelect reads "* FROM users", sees "JOIN" ──
  table_name      = "users"
  join_table_name = "orders"
  consumes "ON" keyword

── Step 5: ParseExpression() recursively builds the AST ──
  LogicalExpression AND
  ├── ComparisonExpression =
  │   ├── ColumnRef users.id
  │   └── ColumnRef orders.user_id
  └── ComparisonExpression =
      ├── ColumnRef users.active
      └── Constant  true

── Step 6: SelectStatement returned ──
  { table_name: "users", join_table_name: "orders", join_condition: AST* }

Parser Grammar

The formal grammar rules that define what the parser accepts.

📐
SELECT Statement Grammar
Including the new JOIN extension
SelectStmt → SELECT * FROM table_name [ JoinClause ] ;
JoinClause → JOIN table_name ON Expression
🌳
Expression Grammar
Recursive descent — handles AND/OR with correct precedence
Expression → Comparison ( ( AND | OR ) Comparison )*
Comparison → Atom [ CompOp Atom ]
CompOp → = | != | > | < | >= | <=
Atom → ColumnRef | Constant
ColumnRef → table_name . col_name | col_name
Constant → INTEGER_LITERAL | true | false
✅
Existing Grammars (Unchanged)
These parsers are NOT modified
CreateStmt → CREATE TABLE name ( col_def ( , col_def )* ) ;
InsertStmt → INSERT INTO name VALUES ( val ( , val )* ) ;
DeleteStmt → DELETE FROM name [ WHERE col = val ] ;
CommitStmt → COMMIT [ ; ]

Function Map

Every parser function — existing and new — and how they connect.

Existing
Parser::Parse()
std::unique_ptr<Statement> Parse(const std::string& sql)
Entry point. Reads the first keyword, uppercases it, and dispatches to the correct sub-parser. Handles: CREATE, INSERT, SELECT, COMMIT, DELETE.
Existing
Parser::ParseCreate()
std::unique_ptr<Statement> ParseCreate(std::istringstream& ss)
Reads "TABLE", table name, then column definitions inside parentheses. Returns a CreateTableStatement.
Existing
Parser::ParseInsert()
std::unique_ptr<Statement> ParseInsert(std::istringstream& ss)
Reads "INTO", table name, "VALUES", then raw values inside parentheses. Returns an InsertStatement.
Modified
Parser::ParseSelect()
std::unique_ptr<Statement> ParseSelect(std::istringstream& ss)
Reads "* FROM table_name". NEW: After reading the table name, checks for the optional JOIN keyword. If found, reads the second table name, consumes ON, and calls ParseExpression().
Existing
Parser::ParseDelete()
std::unique_ptr<Statement> ParseDelete(std::istringstream& ss)
Reads "FROM", table name, optional "WHERE col = val". Does NOT use the Expression AST.
New
Parser::ParseExpression()
std::unique_ptr<Expression> ParseExpression(std::istringstream& ss)
Top-level expression parser. Calls ParseComparison(), then loops to handle AND / OR connectors, building LogicalExpression nodes.
New
Parser::ParseComparison()
std::unique_ptr<Expression> ParseComparison(std::istringstream& ss)
Reads left Atom, then checks for a comparison operator (=, >, <, >=, <=, !=). Builds ComparisonExpression.
New
Parser::ParseAtom()
std::unique_ptr<Expression> ParseAtom(std::istringstream& ss)
Reads a single token. If it contains a ., returns a ColumnRefExpression (e.g., users.id). If it's a number or boolean literal, returns a ConstantExpression. Otherwise, returns a ColumnRefExpression with an empty table name.

3-Stage Optimizer

How the optimizer splits the AST into the fastest possible execution plan.

1
Index Probe
O(log N)
Checks IndexProvider::HasIndex() for each equi-condition column. If an index exists, uses it to directly look up matching rows instead of scanning.
⚡ Fastest — skips full scan
Currently: NullIndexProvider (always skipped)
2
Hash Join
O(N + M)
All = conditions between two columns (e.g., A.id = B.aid) are processed via hash map. Build on the smaller table, probe with the larger.
🔥 Linear — each table scanned once
3
Theta Filter
O(R)
All remaining conditions (>, <, !=, constants) are evaluated against the surviving joined pairs using EvaluateExpression().
📉 Smallest input — only survivors
🧠
Optimizer in Action
How conditions are classified regardless of written order
── Input SQL (user writes conditions in arbitrary order) ──
SELECT * FROM orders JOIN users ON
    users.age > 21                      -- theta (not equi)
    AND orders.user_id = users.id     -- equi-join candidate
    AND orders.total > 50;              -- theta (constant)

── Step 1: Flatten AND-connected conditions ──
conditions = [
    ComparisonExpr(users.age > 21),
    ComparisonExpr(orders.user_id = users.id),
    ComparisonExpr(orders.total > 50)
]

── Step 2: Classify each condition ──
users.age > 21            → NOT equi, NOT column=column  → Stage 3 (Theta)
orders.user_id = users.id → IS equi, IS column=column  → Check index...
                              → IndexProvider::HasIndex("users", "id") → false
                              → Stage 2 (Hash Join)
orders.total > 50         → NOT equi                    → Stage 3 (Theta)

── Step 3: Build JoinPlan ──
JoinPlan {
    index_conditions: []                                       // empty (no indexes)
    equi_conditions:  [{ orders.user_id = users.id }]         // Hash Join
    theta_filter:     AND(users.age > 21, orders.total > 50)  // Post-filter
}

── Execution ──
1. Hash Join on orders.user_id = users.id         → pairs reduced from NxM to ~N
2. Filter: users.age > 21 AND orders.total > 50   → final result
